# RNAFlow Script Tools README

## Overview

This directory contains three tools for processing and validating sequencing-data MD5 checksums:

1. **seq_preprocessor**  : Automatically organize sequencing data from various sources (Short-read and Long-read) with unified naming and directory structure.
2. **json_md5_verifier** : Multi-threaded MD5 checksum verifier based on a JSON report, used to validate data processed by `seq_preprocessor`.
3. **check_md5.py**        : Lightweight concurrent validator for standard `md5sum`-style manifests, suitable for general bulk file-integrity checks.

---

## seq_preprocessor

`seq_preprocessor` automatically organizes sequencing data from various sources. It supports Short-read (paired-end) and Long-read (single-end) data and unifies naming and directory structure.

### Features

- **Multiple input formats**:
  - Illumina (PE): `<sample>_S..._L..._R[12]_...fq.gz`
  - Generic (PE): `<sample>[._][R12|12].fq.gz`
  - SRA (PE): `[SED]RR#######[._][12].fq.gz` (e.g. `SRR######_1.fq.gz`)
  - SRA (SE): `[SED]RR#######.fq.gz` (e.g. `SRR#######.fq.gz`)
  - Long-read (SE): `<sample>.fq.gz`

- **Batch sample renaming**: Use a CSV sample sheet (`--sample-sheet`) to map original IDs (e.g. SRA accessions) to meaningful sample names.

- **Automatic library-type detection**: Auto-detect, process paired-end only, or process single-end only.

- **Smart file handling**:
  - Uses symlinks on Unix systems, pointing to original files without consuming extra disk space.
  - Copies files on non-Unix systems.
  - Automatically validates and rebuilds broken symlinks.

- **JSON report generation**: Produces a detailed renaming report containing original and new paths.

- **SRA special handling**: For SRA data, the MD5 value in the JSON report is marked as `"SRA"`, and no MD5 file is required in the input directory.

- **Structured logging**: Automatically creates timestamped log files; supports `--log-level` / `--log-format` (`text`/`json`).

### Build

```bash
# Build seq_preprocessor into the specified directory
cargo build --target-dir ../Compile_release/seq_preprocessor_x86_64 --release
```

The compiled binary will be located at `../Compile_release/seq_preprocessor_x86_64/release/`.

### Usage examples

```bash
# Auto-detect and process PE and SE data
./seq_preprocessor --input /path/to/raw_data --output /path/to/processed_data

# Rename using a sample sheet
# The CSV must contain 'sample' (original name) and 'sample_name' (new name) columns
./seq_preprocessor --input /path/to/raw_data --output /path/to/processed_data --sample-sheet samples.csv

# Process paired-end (PE) data only
./seq_preprocessor --input /path/to/raw_data --output /path/to/processed_data --library-type ShortRead

# Generate a JSON report and a combined MD5 file
./seq_preprocessor --input /path/to/raw_data --output /path/to/processed_data --json-report report.json --summary-md5 checksums.txt

# Process multiple input directories
./seq_preprocessor --input /path/to/raw_data1 --input /path/to/raw_data2 --output /path/to/processed_data
```

## json_md5_verifier

`json_md5_verifier` is a multi-threaded MD5 checksum verifier based on a JSON report. It validates the integrity of files processed by `seq_preprocessor`.

### Features

- **Multi-threaded concurrent verification**: Specify the number of threads to speed up verification.
- **JSON report parsing**: Reads JSON reports generated by `seq_preprocessor`.
- **Detailed verification results**: Produces a TSV report with timestamp, sample name, file path, expected/actual MD5, status, and message.
- **SRA special handling**: For samples with MD5 value `"SRA"`, the actual MD5 is calculated and recorded without comparison.
- **Progress display**: Real-time progress and statistics.
- **Logging**: Automatically creates timestamped log files; supports `--log-level` / `--log-format` (`text`/`json`).
- **Smart buffering**: Automatically adjusts buffer size based on file size for better performance.

### Build

```bash
# Build json_md5_verifier into the specified directory
cargo build --target-dir ../Compile_release/json_md5_verifier_x86_64 --release
```

The compiled binary will be located at `../Compile_release/json_md5_verifier_x86_64/release/`.

### Usage examples

```bash
# Basic verification
./json_md5_verifier --input report.json --base-dir /path/to/processed_data

# Verify with 8 threads
./json_md5_verifier --input report.json --base-dir /path/to/processed_data --threads 8

# Generate a verification report and specify a log file
./json_md5_verifier --input report.json --base-dir /path/to/processed_data --output verification_report.tsv --log-file custom.log

# Specify a custom buffer size
./json_md5_verifier --input report.json --base-dir /path/to/processed_data --buffer-size 2097152

# Use JSON-format console logs (useful for downstream parsing)
./json_md5_verifier --input report.json --base-dir /path/to/processed_data --log-format json

# Increase console log verbosity (RUST_LOG env var is also supported)
./json_md5_verifier --input report.json --base-dir /path/to/processed_data --log-level debug
```

> Log files are automatically named with timestamps (e.g. `json_md5_verifier_2026-07-22_14-47-15.log`) and saved under `--base-dir`. Use `--log-file` to override the path.

## check_md5.py

`check_md5.py` is a lightweight Python script that speeds up validation of standard MD5 manifests through concurrent processing. It is ideal for validating traditional checksum files produced by `md5sum` or by `seq_preprocessor` (via `--summary-md5`).

### Features

- **Easy to use**: Supports standard `md5sum` format (`<md5>  <filename>`).
- **Concurrent acceleration**: Uses `ThreadPoolExecutor` to significantly speed up large-file validation.
- **Readable logs**: Integrates the `loguru` library for clear real-time console feedback and daily log files.
- **Error handling**: Accurately reports "passed", "file missing", "MD5 mismatch", and "read error" statuses.

### Dependencies

Running this script requires the `loguru` package:

```bash
pip install loguru
```

### Usage

```bash
# Basic usage: specify the checksum list, default 4 threads
python3 check_md5.py --file checksums.txt

# Verify with 8 threads
python3 check_md5.py -f checksums.txt -t 8
```

### Manifest format example

```text
d41d8cd98f00b204e9800998ecf8427e  sample1_R1.fq.gz
e80b5017098950fc58aad83c8c14978e  sample1_R2.fq.gz
```

## Workflow

1. **Organize data**: Use `seq_preprocessor` to organize raw sequencing data. It is recommended to use `--json-report` for a structured report, or `--summary-md5` for a standard checksum manifest.
2. **Validate data**:
   - **Method A (recommended)**: Use `json_md5_verifier` to validate based on the JSON report. This supports SRA special handling and generates a detailed TSV verification report.
   - **Method B (general)**: Use `check_md5.py` to quickly validate against the combined MD5 file (e.g. `checksums.txt`).
3. **Confirm results**: Check the output logs or reports to ensure all files pass validation.

Together these tools form a complete sequencing-data preprocessing and validation pipeline, ensuring data correctness and integrity.
